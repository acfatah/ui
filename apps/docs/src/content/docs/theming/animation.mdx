Components animate with [tw-animate-css](https://github.com/Wombosvideo/tw-animate-css),
a CSS-only set of Tailwind v4 utilities for enter and exit animations.
There is no JavaScript animation library. The shared stylesheet,
`global.css`, imports it right after Tailwind, and the `vue/project-setup`
registry item installs the package.

```css
@import 'tailwindcss';
@import 'tw-animate-css';
```

## Enter and exit

`animate-in` and `animate-out` run a shared keyframe. The other utilities
only set its start or end point, so they combine freely:

| Enter | Exit | Effect |
| --- | --- | --- |
| `fade-in-0` | `fade-out-0` | Opacity from or to 0. |
| `zoom-in-95` | `zoom-out-95` | Scale from or to 95%. |
| `slide-in-from-top-2` | `slide-out-to-top-2` | Translate from or to `--spacing(2)`. |
| `spin-in-45` | `spin-out-45` | Rotate from or to 45°. |
| `blur-in-sm` | `blur-out-sm` | Blur from or to `blur-sm`. |

`duration-*`, `delay-*` and `ease-*` apply to the animation as well as to
transitions.

## How components use it

Ark UI marks an overlay with `data-state="open"` or `data-state="closed"`,
and a positioned one with `data-side` (`top`, `right`, `bottom` or
`left`). Class strings in each component's `styles.ts` key the animation
off those attributes:

```ts
export const popoverContentStyles = `
  origin-(--transform-origin)
  data-[state=open]:animate-in data-[state=open]:fade-in-0
  data-[state=open]:zoom-in-95
  data-[state=closed]:animate-out data-[state=closed]:fade-out-0
  data-[state=closed]:zoom-out-95
  data-[side=bottom]:slide-in-from-top-2
  data-[side=top]:slide-in-from-bottom-2
  motion-reduce:animate-none
`
```

- The content slides in from the side facing its trigger, and
  `origin-(--transform-origin)` makes it zoom out of the trigger rather
  than its own center. Ark sets `--transform-origin`.
- Exit animations play because Ark's presence logic waits for
  `animationend` before it unmounts the element. A `transition-*` exit
  does not delay unmounting; use `animate-out`.

## Customize

Animations live in the component's class string, so change them in the
installed `styles.ts`:

```ts
// @ui/popover/styles.ts: slower, no zoom
data-[state=open]:animate-in data-[state=open]:fade-in-0
data-[state=open]:duration-300
```

Keep enter and exit symmetric. An exit shorter than its enter reads as a
snap.

## Reduced motion

Animated components add `motion-reduce:animate-none`, so they appear and
disappear instantly when the user asks the system for reduced motion. Add
it to any animation you write yourself.

<Aside type="note">
  `motion-reduce:animate-none` removes the exit animation too, so the
  element unmounts at once. That is intended.
</Aside>

## Custom keyframes

tw-animate-css covers fades, zooms, slides, spins and blurs. It also
ships `accordion-*` and `collapsible-*` height animations, but those read
Radix, Reka and Bits height variables, not the `--height` Ark sets, so
they jump straight to `auto` here.

A component that needs another keyframe ships it in its own registry
item instead of the shared `global.css`. The `css` field of
`_registry.ts` is merged into the consumer's stylesheet on install. Pick
a name that does not clash with tw-animate-css:

```ts
css: {
  '@theme inline': {
    '--animate-ark-collapsible-down': 'ark-collapsible-down 0.2s ease-out',
  },
  '@keyframes ark-collapsible-down': {
    from: { height: '0' },
    to: { height: 'var(--height)' },
  },
},
```

This generates an `animate-ark-collapsible-down` utility.

## Without project-setup

Every component item that animates lists `tw-animate-css` in its
`dependencies` and adds `@import "tw-animate-css"` through its `css`
field. It still animates in a project that never installed
`vue/project-setup`, provided Tailwind is set up.
